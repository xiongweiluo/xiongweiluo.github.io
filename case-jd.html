01Eight workspaces. Different ways to work.

Configure a fleet, trace a vehicle, resolve a repair—each workspace supports a different operational task.

02From a request to a deployment.

Operations teams track requests and apply for vehicles in one workspace. I connected the overview to grouped forms and region-dependent vehicle selection.

03Keep spatial work in context.

I grouped 47 map design nodes into 13 runtime states, keeping drawing tools, layers and version controls in the same workspace.

04Give each role the right access.

I preserved the permission hierarchy: choose a template, then edit its resources and actions in a dedicated drawer.

05The collaboration behind the product.

07Comparing agent collaboration.

I tried three approaches and used a persistent multi-agent team. The experience raised a broader question: how should collaboration evolve as the workload grows?

Questions for further research.

I plan to compare these three setups across repeated development cycles, focusing on:

Memory across iterations
When does retained context help, and when does it preserve outdated decisions? Compare continuing histories with updated project records.
Dependencies & parallel work
When does parallel work save time, and when do coordination and integration outweigh it? Compare independent changes with cross-module tasks.
Delegation & information loss
What gets lost when sub agents report back to the lead? Compare free-form summaries with structured handoffs, including constraints and unresolved issues.
